## Part 2 - Redesign direction (2026 baseline)

Constraints kept: static site, Vite, vanilla JS, GitHub Pages, no framework, and no runtime third-party dependency except explicitly approved analytics/feed calls. Any approved third-party runtime call must be consent-gated where applicable, lazy-loaded, documented, and verified in browser network traces.

### 2.1 Design system foundation
- **OKLCH token layer** in `@layer tokens`: perceptually uniform ramps for surface/text/accent so dark and light are generated from the same hues rather than hand-tuned twice.
- **Fluid type + space scale** with `clamp()` (a modular scale, `--step--2` through `--step-6`), replacing every hardcoded `rem` font-size in markup.
- **`@layer reset, tokens, base, layout, components, utilities`** so specificity is structural, not accidental.
- **Self-hosted Inter variable** (woff2, `font-display: swap`, latin subset) plus a display face for headings; removes the Google Fonts round trip and the FOUT.
- **`color-scheme: light dark`** + `light-dark()` for form controls and scrollbars, with the existing `data-theme` override retained for the manual toggle.

### 2.2 Visual language
Move off uniform glassmorphism (a 2021 look) to a layered, high-contrast editorial style:
- **Bento grid** for expertise and case studies - asymmetric cells, one hero cell carrying a metric.
- **Depth via elevation tokens and subtle grain**, not blanket `backdrop-filter` (which also costs paint on every panel).
- **Gradient mesh accents** confined to the hero and section transitions, rendered as a single CSS gradient rather than two blurred 400px divs.
- **Metric-forward cards**: each expertise/case cell leads with a number (migration scale, LCP delta, WCAG level, uptime).
- Retain the purple/teal identity but re-derive it in OKLCH for consistent chroma across themes.

### 2.3 Modern CSS platform features (all baseline-available in 2026)
- **Container queries** for card internals so components respond to their cell, not the viewport.
- **Scroll-driven animations** (`animation-timeline: view()`) replacing the IntersectionObserver reveal - removes JS and respects reduced motion via a plain media query.
- **View Transitions API** for theme switch and in-page anchor navigation, feature-detected.
- **`:has()`** for nav open state and card hover coordination, removing JS class toggling.
- **`text-wrap: balance`/`pretty`** on headings and paragraphs.
- **`@starting-style` + `transition-behavior: allow-discrete`** for the mobile menu and back-to-top so `display` transitions cleanly (fixes A7 without JS timers).
- **Popover API + anchor positioning** for the mobile nav panel, replacing the manual show/hide.

### 2.4 Structure and content
- Restore **Selected Work** as a real case-study grid driven by `src/data/projects.js`, but curated: 6-9 flagship engagements with client, scope, stack, and one measurable outcome each. Filter chips (All / Drupal / WordPress / AI) rebuilt accessibly as a radio-group toolbar.
- **AI Innovation** stays as the featured project, restyled as the bento hero cell.
- **Latest Writing**: single source of truth. Fetch one feed, cache it with a stale-while-revalidate SW strategy, and drop the cache-buster.
- **Hero**: one primary CTA (Get in touch) plus one secondary (Download CV); GitHub and LinkedIn move to a persistent icon rail.
- Add a short **"How I work"** band (discovery -> architecture -> delivery gates) - the differentiator for an architect-level portfolio.

### 2.5 Motion
- All motion behind `@media (prefers-reduced-motion: no-preference)`.
- Marquee gets a real pause/play control and pauses on focus-within (fixes C2).
- Typewriter replaced with a reduced-motion-safe rotating role that swaps whole words on a view transition, with the animated node removed from the h1 accessible name and a static fallback (fixes C3, C8).

## Part 3 - Execution plan

Phase ordering is deliberate: correctness first, so the redesign is not built on dead code.

**Phase 0 - Isolation**
- Work in a linked worktree off `main`; the `main` checkout stays parked on `main`.
- Baseline: `npm ci`, `npm run build`, capture current Lighthouse and axe scores plus full-page screenshots (390 / 768 / 1440) for before/after evidence.

**Phase 1 - Remove dead weight** (A2-A5, A7, D2, D3, E2, E3)
- Delete `src/counter.js`, `src/javascript.svg`, the duplicate CVs, the dead scroll-progress listener, and the double `setupTypewriter`/`setupScrollReveal` calls.
- Replace the back-to-top display/opacity timer logic with a CSS-driven visible state using `@starting-style` and `transition-behavior: allow-discrete`, then verify repeated scroll-up/scroll-down sequences cannot leave it visible below the threshold.
- Delete `vanilla-tilt` (the redesign uses CSS-only hover elevation).
- Prune `public/images/projects/` to the curated case-study set; convert survivors to AVIF plus WebP with `<picture>` and `srcset`.
- Rewrite `public/sw.js` as a stale-while-revalidate cache for the writing feed and static assets, or remove it if it earns nothing.

**Phase 2 - Extract and tokenize** (D6, E1)
- Move every inline `style` attribute out of `index.html` into layered CSS with semantic class names.
- Introduce the token layer, fluid scales, and `@layer` order.
- Remove every inline event handler; bind in `main.js` via delegation (B2).

**Phase 3 - Rebuild the page** (Part 2)
- New semantic skeleton: skip link, `<header>`, `<main>`, landmark labels, `scroll-margin-top` on anchor targets.
- Bento expertise grid, restored case-study grid, how-I-work band, restyled AI Innovation cell, contact.
- Theme toggle actually rendered and wired (A1), with `color-scheme` and view transitions.
- Self-hosted fonts and locally vendored tech-stack SVGs (D1, B4).

**Phase 4 - Accessibility pass** (C1-C8)
- Focus-visible ring token applied to every interactive element.
- Marquee pause control, reduced-motion guards, decorative icons replaced with inline SVG marked `aria-hidden`.
- Mobile nav via the Popover API with correct `aria-expanded`/`aria-controls`; verify ESC, light-dismiss, focus movement into the opened menu, focus return to the trigger on close, tab order, and a non-Popover fallback for browsers that lack the required behavior.
- Fix `.section-title` gradient to a token pair that meets AA in both themes.

**Phase 5 - Hygiene and guards** (B1, B3, B5, A6, A8, D5, E4-E7)
- Deliver project data through `dataset` plus a `Map`, not `onclick` string interpolation.
- Gate GA4 behind a consent banner with default-deny behavior: no GA script, cookie, storage write, or analytics request before opt-in; persist opt-in/opt-out; provide a visible way to revoke consent; verify the network panel in accepted, rejected, and cleared-storage states.
- Relative asset paths everywhere so `base: './'` holds under a subpath.
- Derive the copyright year; replace the dead placeholder fallback with a local SVG.
- Drop the dev.to cache-buster; rely on SW stale-while-revalidate.
- Add ESLint (flat config) plus Prettier and `npm run lint`, and a CI job running lint, build, and a Lighthouse CI budget on PR.
- Real favicon set and `manifest.json` icons; regenerate `sitemap.xml`.

**Phase 5b - Browser-confirmed defects** (G1-G5)
- G1: the rotating role must never leave the headline as a bare conjunction. Render the full role text (no leading `&` fragment) and keep a complete static value in the markup as the no-JS and first-paint state.
- G2: sanitize the feed `description` - strip MDX/JSX import and component lines before rendering, and fall back to a trimmed plain-text excerpt.
- G3: validate `cover_image`/`social_image` and substitute a local SVG placeholder when the feed returns the dev.to "image no longer exists" asset or any non-200 image.
- G4: the bento layout must place all expertise cells deliberately at every breakpoint - no orphan cell on its own row at 1440.
- G5: eliminate the 390px horizontal overflow at its source (currently `documentElement.scrollWidth` 446 vs 390). `body { overflow-x: hidden }` is not an acceptable fix; find the overflowing element and constrain it. Verify `scrollWidth === clientWidth` at 320, 390, 768, and 1440.

**Phase 6 - Verification** (evidence required before done)
- `npm run build` clean; bundle size reported before and after.
- Lighthouse (mobile and desktop): Performance >= 95, Accessibility 100, Best Practices >= 95, SEO 100.
- axe-core: zero violations at 390 / 768 / 1440.
- Manual keyboard walkthrough: skip link -> nav -> filters -> cards -> modal -> back-to-top, with visible focus at every stop.
- Both themes verified for contrast; forced-colors sanity check.
- `prefers-reduced-motion: reduce` verified to stop marquee, reveal, and role rotation.
- Before and after screenshots at the three viewports, inspected, attached to the handoff.
- Service worker and feed verification: first load, reload, offline load, stale-cache refresh, failed feed response, and SW update from an existing registered version must all behave without console errors or broken UI.

## Part 4 - Open decisions (stated assumptions, not blockers)

1. **GA4**: assumption is keep GA4 but gate it behind consent. Alternative is dropping it for a cookieless counter. Proceeding with consent-gated GA4.
2. **Case-study content**: `src/data/projects.js` has 40+ entries with client names. Assumption is that anything already public in that file is publishable; curation is by relevance, not by new NDA review. Each selected case study must have client, scope, stack, and one supportable measurable outcome already present or derivable from public content; otherwise use a non-metric presentation for that card rather than inventing or implying a number.
3. **Display typeface**: assumption is a single self-hosted variable grotesk pairing (Inter var body plus a tighter display cut for headings) rather than adding a serif.
4. **Blog feed**: assumption is dev.to stays the data source and the "reference blog" link points at the same content, or the agent-blog gains an RSS/JSON feed. Whichever exists is used; the mismatch is resolved, not left.
